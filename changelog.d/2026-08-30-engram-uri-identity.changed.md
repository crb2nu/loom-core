- **Engrams: one identity — the URI — on every surface** (`pkg/agentcontext/svc_engrams.go`, `internal/hud/bridge/agent_engrams.go`): `agent_engram_list` and `agent_engram_recall` used to serve the backing memory-item id as `"id"` while the full graph keyed nodes by `uri` with no id at all — so a response's own `prerequisites` (always URIs, like graph edges, `Pattern.engrams`, and the verify/graph tool inputs) could not be resolved against its own id space, and clients grew tolerant three-way matchers to survive it. List/recall items now serve `id == uri` (the storage id rides along as `memory_id`; legacy recipes without a URI keep the storage id so they stay uniquely addressable), and graph nodes — dangling-prerequisite stubs included — carry an explicit `id == uri`. Every edge endpoint now resolves against the node id set by construction, pinned by an identity contract test. The HUD bridge's empty-id→URI fallback stays for mixed-version deployments against an older agent-context.
