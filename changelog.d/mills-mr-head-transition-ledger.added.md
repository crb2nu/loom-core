- Mills: MR source-head movements are now durable, restart-safe ledger rows instead of a local variable (#374). Migration `016_mr_head_transitions.sql` adds `mr_head_transitions` (one immutable row per movement, `UNIQUE(pipeline_run_id, seq)`, partial index on unsettled rows), backed by `store.MRHeadTransitionDAO` with append-then-settle CAS semantics (`Open` refuses a second unsettled row so a non-idempotent rebase can never be issued twice for one movement; `Settle` compare-and-swaps on `settled_at IS NULL`). `clients.GitLabClient.ObserveHead` classifies a movement from GitLab's own after-the-fact record — MR `versions` as the primary witness, `events?action=pushed` as corroboration, and `noop` decided only by SHA equality on the MR itself so a lagging activity feed can never read as "nothing happened". `GET /api/mills/pipeline/runs/{id}/transitions` exposes the ledger (open read, `[]` never `null`).
- Mills: a head that moves after CI goes green can no longer be merged on the strength of the old verdict. `ci_watch` stamps the run's settled-movement fence as the `ci_transition_seq` stage artifact next to `ci_sha`, and the merge stage's authorization rebuild (`ciMergeRequestFrom`) fails closed with `ErrMergeAuthorizationStale` when the ledger has advanced past that stamp — composing with, not replacing, the existing project/branch/SHA identity checks. On a merge-stage source-SHA mismatch the runner mints an `external` transition row and rewinds the run to `post_implement_gate`, so every source-sensitive gate plus a fresh CI cycle re-run for the successor SHA and the merge binds to a revision that was actually tested; `LOOM_MILLS_MERGE_MAX_HEAD_TRANSITIONS` (default 1) bounds rebase↔push ping-pong by escalating instead of re-gating once the budget is spent. Legacy runs carry no stamp, read 0 against an empty ledger, and merge exactly as before — no backfill. No caller triggers a rebase yet; the observation path only records what GitLab already did, and `TestMerge_Persistent422ReturnsWithoutRebase` still proves the merge stage issues no rebase.
