- **Bump the pinned spawn-pod Codex CLI to 0.143.0 so per-stage gpt-5.6 models work** (`internal/hud/spawn.go`, `internal/hud/spawn_test.go`): the Mills per-stage model pass-through shipped a `model=gpt-5.6-sol` (and `gpt-5.6-terra`) down to `codex exec --model`, but the spawn-runtime image pinned `@openai/codex@0.130.0`. OpenAI gates the gpt-5.6 model family behind a minimum Codex CLI version, so every such spawn authenticated, started a turn, then died on an HTTP 400 `invalid_request_error` — `"The 'gpt-5.6-sol' model requires a newer version of Codex. Please upgrade to the latest app or CLI"` — surfaced to the operator only as the misleading stdout tail `Reading additional input from stdin...` and escalating after 3 attempts (2026-07-18 issues #347/#349/#350/#351). The default codex pin moves to `0.143.0` (verified to run gpt-5.6 turns; 0.130.0 cannot), covering both the k8s Dockerfile install (`agentCLIInstallLines`) and the harvester-vm SSH installer (`agentCLIInstallShell`). A new `SPAWN_CODEX_VERSION` env override (mirrors `SPAWN_CODEX_MODEL`, validated to a strict semver/prerelease pattern before it reaches a root `npm install`) lets operators clear a future version gate with an env flip instead of a loom-core rebuild. Regression coverage pins the exact codex argv (with and without a per-request model, plus the headless `codex exec` + `< /dev/null` safety invariants), exercises the version resolver including shell-injection rejection, and floors the compiled pin at 0.143.0.
