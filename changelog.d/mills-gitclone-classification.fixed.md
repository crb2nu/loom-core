- **Classify a spawn git-clone failure by its real git error instead of an opaque `exit_code=128`** (`internal/devbox/backend/k8s_wait.go`, `internal/devbox/backend/k8s_build.go`, `internal/devbox/backend/k8s_runtime.go`, `pkg/mills/pipeline/git_clone_class.go`, `pkg/mills/pipeline/error_class.go`, `pkg/mills/pipeline/runner.go`, `docs/MILLS.md`): a plan_slice/implement spawn whose git-clone init container failed because the **target repo did not exist** (or a bad ref / auth / DNS failure) surfaced only as `image build failed: buildah build failed: container git-clone terminated exit_code=128 reason=Error` and escalated as generic **infra** — the actual GitLab 404 was invisible (live 2026-07-16: a plan targeting `services/familyforge`, a repo that did not exist, escalated with no visible cause). The k8s backend now reads the **failed init container's** logs (not the empty buildah-container logs), credential-redacts the clone URL, and appends the real `fatal: …` git line to the spawn/build error at both spawn surfaces (buildah build pod and runtime pod). A new deterministic classifier (`ClassifyGitCloneError`, wired into `Classify` **before** the generic `buildah build failed`/`image build failed` infra needles) maps that line to an actionable class + message: repository-not-found / bad-ref / auth → **terminal `config`** (escalates on first sight without burning retries — an identical retry can only fail identically — with guidance to create the GitLab repo / enable plan→repo bootstrap, fix the branch, or fix the spawn git token), and a DNS/connectivity blip → **`transient`** (retries instead of escalating a human). The escalation now carries `escalation_class=config` / `retryable=false` so bounded auto-requeue correctly leaves it for a human. An `exit_code=128` with no captured git message fails closed to a safe generic terminal-config note rather than mis-classing as infra.
