- **Fix the off-by-one that corrupted buffered stdout tails** (`internal/devbox/backend/stream_exec.go`): the streaming exec's 20-line tail ring took its write index after incrementing the line counter, so line N landed at `N%size` instead of `(N-1)%size`. The first wrap evicted line 2 while line 1 survived, and the reader — which assumed the correct layout — replayed that stale line inside the tail. The damage window is the first wrap: for a command emitting 21–39 stdout lines the tail dropped a real line and replayed line 1 out of order (at 38 lines it read `… 20, 1, 21`); at 40+ lines the stale entry has been overwritten and the old indices coincidentally agreed again. That window covers most short command output, and anything reading the tail — the spawn finalizer, the buffered-path parser replay that sees only this tail — took the misplaced line as adjacent context. The ring is now an extracted, unit-tested `tailRing`.
