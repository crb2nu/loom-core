- **Fail closed when the canonical roadmap-intent store is empty, and actually fill it** (`pkg/mills/runner/runner.go`, `pkg/mills/council/brief.go`, `pkg/mills/policy.go`, `pkg/policy/policy.go`): the council brief now carries a structured `IntentsMissing` flag alongside the Markdown `intents_missing` marker (also exposed as `intents_missing` in the `brief_sources` API projection), and `Runner.Execute` blocks scheduling on it — returning `runner.ErrIntentsMissing` before any reviewer or editor spend rather than letting the council plan against no stated intent. The guardrail defaults to on and is overridable with `council.require_roadmap_intents: false`; an omitted key, a nil policy, and `Default()` all resolve to fail-closed. The same change fixes the root cause of the empty store: `council.ExtractFromFile` and `Roadmap.SyncToStore` had no callers, so a new best-effort `roadmap` stage now extracts `$LOOM_MILLS_REPO_ROOT/ROADMAP.md` into `roadmap_intents` before the brief is compiled, recording each bullet's git blob SHA. A missing, unreadable, or unparseable roadmap logs and degrades to the intents-missing path instead of failing the run, and a roadmap that parses to zero intents is skipped rather than synced so `DeleteStale` cannot wipe the store and self-inflict a permanent block.
