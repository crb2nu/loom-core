- **Codex config generator now owns the loom-managed block of `~/.codex/rules/default.rules`** (`pkg/generator/codex_rules.go`, `pkg/sync/ops_codex.go`, `pkg/sync/ops_regen.go`, `mcp/context/registry.yaml`): Codex's workspace-write sandbox force-mounts `.git` (including resolved worktree gitdirs) read-only by design with no config override ([openai/codex#15505](https://github.com/openai/codex/issues/15505)), and `approval_policy = "never"` removes the escalation prompt — so autonomous `git commit`/`push` wedged with "cannot lock ref ... Operation not permitted". The vendor-supported fix (shipped by hand 2026-07-25) is an execpolicy `prefix_rule(pattern = ["git"], decision = "allow")` in `~/.codex/rules/default.rules` (per <https://learn.chatgpt.com/docs/agent-configuration/rules.md>), which runs matched commands outside the sandbox without prompting. `loom sync codex --regen` now renders that curated block from `platform_permissions.codex.settings.rules` and merges it marker-wise into the home file, preserving user-authored and Codex-TUI-auto-appended rules outside the markers (same regen-survival contract as the flightdeck hooks merge). The file is intentionally not an `ExtraGeneratedFiles` entry — plain copy would clobber appended approvals and the workspace sweep would delete hand-authored repo-local `.codex/rules/` files.
