- **S4 pod-owned execution supervisor: spawned agent turns survive a mobile-hud crash with process continuity** (`internal/hud/spawn_supervisor.go`, `internal/hud/spawn_supervisor_reattach.go`, `internal/hud/spawn.go`, `internal/spawn/types.go`, `docs/runbooks/mills-workflow-s1c-killtest.md`): moves agent-turn execution ownership OUT of the mobile-hud exec session and INTO the spawn pod, closing the loom-core#300-class orphan for good and satisfying the S1c process-continuity contract. Previously mobile-hud EXEC'd into the pod and drove the agent CLI + a foreground `sleep N` completion hold directly; force-deleting mobile-hud severed that exec, and restart recovery RE-DROVE a fresh turn (new completion-wrapper/hold `(PID, starttime)`) — outcome-exactly-once held, but process continuity did not, so the runbook's stronger contract (the SAME `(hold, wrapper)` pair must survive BOTH crashes) was expected to FAIL. Now, on the streaming (k8s) substrate, the wrapped agent+hold is launched under a detached, PID-1-reparented in-pod **reaper** (`setsid`, stdio off the exec stream) that records the turn outcome durably on the pod filesystem and lingers as `sleep infinity` so its own exit cannot orphan a zombie under the pod's non-reaping `sleep infinity` PID 1. mobile-hud only LAUNCHES the reaper and TAILS its log; when mobile-hud dies the launcher dies but the reaper+wrapper+hold survive. A restarted mobile-hud **re-attaches** (`classifyInterruptedSpawn` → `interruptedReattach` for `State.Supervised` keyed spawns; `recoverInterruptedSpawns` probes the reaper and dispatches reattach/collect/re-drive via `classifySupervisorProbe`) — observing status, streaming the tail, and collecting the outcome exactly once — instead of re-driving. Exactly-once outcome stays anchored on the deterministic `IdempotencyKey` + journal `readThrough`; the supervisor adds continuity, never a second outcome path. The !1025 terminal-freeze fence is preserved (reattach routes through `completeSpawn`/`failSpawn` and can never resurrect a terminal record), as is the recovery-before-reconcile boot ordering. Delivery needs no new image dependency: the completion wrapper (unchanged `wrapAgentCommandWithCompletionHold` output — the exact string the S1c killtest matches) and the reaper body are written into the pod as files via the existing base64 injection pattern, so neither killtest wrapper substring ever appears in a long-lived process argv (the killtest still sees exactly one wrapper). Backward compatible: pods launched by an older controller carry `State.Supervised=false` and recover via the unchanged re-drive path; a died-mid-flight supervised reaper also falls back to re-drive for liveness. The mobile-hud re-attach emits the accepted killtest dedupe phrase `idempotent spawn re-attach (already exists)`, so the S1c gate's PASS-1 durable-dedupe proof is satisfied with no contract change. Gated by `LOOM_SPAWN_SUPERVISED_EXECUTION` (default on; set `false` to roll back to the legacy exec+re-drive path without a code revert).
