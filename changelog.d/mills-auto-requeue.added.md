- **Bounded auto-requeue for retryable Mills escalations** (`pkg/mills/reconciler_auto_requeue.go` `SweepAutoRequeue`, `pkg/mills/policy.go` `AutoRequeuePolicy`, `pkg/mills/store/dao_events.go` `CountBySubjectKind`/`CountByKindSince`): the reconciler now requeues eligible escalated backlog items itself instead of parking them for a human to POST `/api/mills/pipeline/runs/{id}/start?requeue=1`. Each tick — after the ghost-spark sweep, so a run whose MR merged out-of-band is reaped as merged, never re-implemented — it flips a small, capped number of escalated items back to queued through the same claim-version-guarded transition the manual requeue uses. Eligibility is class-driven: `infra`/`transient`/`transient_quota` after a cooldown (default 10m); an item escalated for an external dependency only once the matching incident clears (below the degraded-mode threshold in the rolling window); `code`/`config`/unclassified never (a human signal). An item whose latest run has an open/merged MR is skipped (its branch needs fixing or the ghost-spark sweep owns it). Hard caps guard the blast radius: per-item lifetime (default 2, counted from durable events so it survives an operator restart), fleet-wide rolling-24h (default 6), and never into an exhausted `MaxRunsPerDay` run budget (`CountBudgetedSince`). Every requeue appends a first-writer-wins audit event, increments `mills_auto_requeues_total{class}`, and surfaces in the KPI snapshot as `auto_requeues`. Config lives under `pipeline.auto_requeue: {enabled, cooldown_minutes, per_item_max, per_day_max}` (default-ON, `Validate()`-bounded). Escalation-issue commenting is a wired-when-available optional hook (`AutoRequeueIssueCommenter`); log-only until the Escalator's issue client is exposed to the reconciler. Pinned by table-driven tests: class eligibility, cooldown, per-item cap persistence across restart, rolling per-day cap, budget-exhausted skip, active-external-incident skip, open-MR skip, event-appended-once, and a stale-claim clean skip (no error storm).
