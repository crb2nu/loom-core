- **HUD: one pattern picker, one materials form, one validator** (`internal/hud/frontend`): the Pattern Loom page and the Spin-a-plan dialog each carried a full catalog picker and materials form with diverging semantics — most consequentially, the dialog force-seeded every bool material to explicit `false`, silently overriding a pattern's `default: true`, while the page couldn't validate enums and collected only one error at a time. Both now render the shared `PatternCardPicker` (status-grouped ordering everywhere; the dialog keeps its approved-only selection policy via a prop) and `PatternMaterialsFields` (tri-state bool selects whose empty option names the default), and both validate through the one `buildMaterials`, whose bool handling is now tri-state: an untouched bool is omitted so the stamp applies the pattern's declared default. The dialog also drops its private catalog fetch for the shared patterns store — its isolation rationale (not disturbing the page's status filter) died when the filter became view-state.
