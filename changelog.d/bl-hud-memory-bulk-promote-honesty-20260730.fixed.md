Memory bulk Promote and Demote no longer claim success the daemon refused. `memoryStore.promote`/`demote` returned `Promise<void>` and recorded failures only in the shared, non-per-call `error` field, so `MemoryPanel`'s bulk passes had nothing to branch on and toasted "N items promoted" even when every POST came back 500 — the same dishonest-success class swept elsewhere in !1321. Both store methods now return `Promise<boolean>` like the neighbouring `addItem`/`deleteItem`, and `bulkPromote`/`bulkDemote` count failures and report the same three ways `bulkDelete` already did (success, error when the whole pass failed, warning naming the counts on a partial pass). The single-row and drawer Promote/Demote buttons likewise toast an error instead of an unconditional "Memory promoted".
