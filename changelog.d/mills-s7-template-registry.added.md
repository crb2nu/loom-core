- **mills: S7 — closed workflow-template registry with clamped selection** (`pkg/mills/workflow/registry`, `.loom/134 §S7`). Imperative workflow programs are now named, versioned, immutable registry entries (first template: `implement-gate@v1`) rendered deterministically from frozen parameters — numerics clamp to per-template `[min,max]` specs (fuzz-tested idempotent, NaN/±Inf → default), strings come from closed enum vocabularies (a disallowed token rejects, so nothing unvalidated is ever interpolated into Starlark). Backlog items select a template via new `ItemPolicy` fields; the council's backlog mutator strips invalid selections at authoring (item lands as a normal DAG item) and admission-side `ResolveItemSelection` fails closed on unknown templates, defers explicit selections while `workflows.enabled=false`, and freezes engine + template + version + interpreter pin + clamped params + the template's content hash onto the run. At execution the interpreter dispatches non-canary templates through the registry, refuses non-imperative engine rows (discriminator guard), terminalizes unknown/drifted templates instead of zombie-looping, and re-verifies the frozen content hash against the compiled-in registry — a template whose source changed under an in-flight run fails closed, mirroring the interpreter version pin. The registry is a leaf package so the council guard imports it without a cycle; agent-type tokens are pinned to `pkg/mills/worker` by a parity test. Reconciler/claim-kernel wiring (starting imperative runs from queued items) is the follow-up slice; until then the machinery is reachable via `CreateRunFromSelection` and dormant in production (`workflows.enabled: false`).
