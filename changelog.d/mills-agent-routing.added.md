- **Per-item agent routing for the Mills operator — claude-code and codex implementers running simultaneously** (`pkg/mills/agent_routing.go`, `pkg/mills/policy.go`, `pkg/mills/pipeline/dispatcher.go`, `cmd/loom-mills-operator/main.go`, `docs/MILLS.md`): a new `pipeline.agent_routing` policy block routes *individual backlog items* to a harness+model, so plans authored by a frontier model can queue UI/design/frontend work to the `claude-code` harness and backend/systems/infra work to `codex` — both fleets running at once on the same k3s substrate. Rules are an ordered, first-match-wins list; each `match` accepts any of `labels`, `priority` (P0–P3), and `path_globs` (doublestar, matched against the normalized union of the item's slice file paths), with populated criteria AND-ed and entries within a criterion OR-ed. Each `route` names a required `agent` from the closed `claude-code|codex|gemini` vocabulary plus an optional vendor-native `model`. An `agent/claude-code` or `agent/codex` label on the item overrides every rule; an unrecognized `agent/*` suffix, or two labels naming different harnesses, are ignored with a warn log rather than failing or order-dependently wedging dispatch. Full precedence, owned by `cmd/loom-mills-operator.spawnRouteFor`: `LOOM_MILLS_SPAWN_AGENT`/`LOOM_MILLS_SPAWN_MODEL` env break-glass > item label > first matching rule > `pipeline.stage_agents` > `claude-code` default. Model follows agent everywhere — a route's own model wins, a route keeping the baseline agent inherits `stage_models[stage]`, and any re-target of the vendor (routing *or* the env break-glass) drops the pin so `codex exec --model claude-opus-5` can never be issued during a failover. The dispatcher seam widened accordingly: `SpawnWorker.AgentFor`/`ModelFor` (stage-only, resolved separately) collapse into a single item-aware `RouteFor(ctx, stage, item) mills.AgentDecision`, so agent and model resolve together and the backlog item reaches agent resolution. A dispatch that routing actually claimed appends a `pipeline.stage.agent_routed` event (`{item, stage, agent, model, decided_by, outcome}`, `decided_by` ∈ `label|rule:<idx>`) and stamps the same triple into the stage's `agent_routing` artifact, so "why did this item go to codex?" is answerable from the event stream; the `stage_agents`/`default`/`env` rungs are deliberately not recorded so an operator who never opted in gains no per-dispatch rows in the unpruned events table. Routing applies only to the SpawnWorker-driven stages (`plan_slice`, `implement`, `pr_self_review`) and never touches gate/judge model selection. Rules are validated at policy load — closed agent vocabulary, non-empty match, valid priority bands, compilable globs, sane model tokens, rule-count cap — even behind `enabled: false`, and the entire feature (including the `agent/*` label) is inert when the block is absent.
