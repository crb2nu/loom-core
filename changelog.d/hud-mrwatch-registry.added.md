- HUD: branch→merge-request status registry (`internal/hud/mrwatch`, slice M1 of the "no MR left behind" spec). A context-cancellable, jittered poller lists open MRs for a configurable set of GitLab projects (`LOOM_MRWATCH_PROJECTS`, default `services/loom-core`; `LOOM_MRWATCH_INTERVAL`, default 90s), reusing the mills GitLab client/token wiring (`GITLAB_API_URL`/`GITLAB_TOKEN`). Because GitLab's list endpoint returns no pipeline info, each poll enriches up to `LOOM_MRWATCH_MAX_ENRICH` (default 20) newest-updated MRs per project with a bounded single-MR GET that carries `head_pipeline`; an enrichment failure degrades that MR to its list view. Each open MR is classified into a stall taxonomy (`ok`, `awaiting_pipeline`, `ci_running`, `ci_failed_flaky`, `ci_failed_deterministic`, `conflict`, `automerge_unarmed`, `pipeline_skipped`, `stale_branch`, `draft_idle`), with flaky-vs-deterministic reusing `pkg/mills/audit.ClassifyCIFailureMessage`. An unreachable GitLab degrades to the last good snapshot marked stale — it never crashes or blocks HUD init. New read-only REST endpoints: `GET /api/agent/mr-status?branch=<b>[&repo=<p>]` and `GET /api/mrwatch/summary`.
