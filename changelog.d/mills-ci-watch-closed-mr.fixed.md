- **Stop `ci_watch` when an operator closes the merge request mid-watch** (`pkg/mills/clients/gitlab.go`): `PollPipeline` checked `mr.State` only on the headless path, so a closed or locked MR that already had a head SHA kept polling to the full deadline and then reported a generic pipeline timeout — spending both watch extensions on an MR GitLab will never build again. It now stops on the observation that sees the close and wraps the existing `ErrMergeRequestClosed` (terminal `config`). A `merged` MR deliberately keeps polling: its head pipeline still resolves normally, and failing it would escalate a run whose work actually landed.
