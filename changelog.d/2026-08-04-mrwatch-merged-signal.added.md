- Retain recently-merged MRs in the HUD mrwatch registry with an explicit `merged` state (and `merged: true` / `merged_at`) on `GET /api/agent/mr-status` for a bounded 72h window (`LOOM_MRWATCH_MERGED_RETENTION`, `<=0` disables), so a merge is a positive signal instead of an MR silently vanishing — this activates the plan-store truth sweep, which advances plan/slice phases only on an explicit merged marker (`internal/hud/mrwatch/classify.go`, `internal/hud/mrwatch/poller.go`, `internal/hud/domain/mrwatch/handlers.go`, `pkg/mills/clients/gitlab_mrlist.go`). Closed-unmerged MRs classify as `closed` and are never retained or conflated with merged; the mrwatch shepherd's action set is unchanged.
