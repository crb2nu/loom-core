- **The pipeline run drawer now shows the run's current-belief verdict** (Trustworthy Verdicts S4) (`internal/hud/frontend/src/lib/components/mills/PipelineRunDetail.svelte`, `internal/hud/frontend/src/lib/stores/mills.svelte.ts`): the operator has been shipping `evidence.verdict` on the run-detail GET since S1, and the drawer ignored it. It now renders the verdict class as a chip in the run summary, with a correction accent, a tooltip citing the supersede `source` and time, and a compact `was <prior_class> → <class> via <source>` history line whenever something superseded the original class — so a rescued escalation reads `merged_after_escalation` beside a row that still says `escalated`. The class is rendered verbatim and never folded into a plain `merged`, which is the whole point of the label: a corrected run must stay distinguishable from a clean one. The chip appears only when the verdict says something the header's state pill does not (it was corrected, or its class differs from the row state), so live runs — which arrive carrying `{class: <state>, occurred_at: "0001-01-01T00:00:00Z"}` rather than a null verdict — render no chip and no year-1 timestamp. A missing `evidence` block or an explicit `verdict: null` from an older operator renders nothing.
