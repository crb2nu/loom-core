- **Make operator-triggered Council runs durable and edge-disconnect safe** (#334) (`pkg/mills/runner/runner.go`, `cmd/loom-mills-operator/`): the runner now splits admission from execution (`Admit` commits the `council_runs` row and its budget reservation; `Execute` does the long work), so the new `POST /api/mills/council/async` can return `202 {run_id, status, status_url}` with an **already-committed** id and run the pass on the operator-lifetime context — a Cloudflare/nginx disconnect at ~100s can no longer cancel a Council pass, and callers poll `GET /api/mills/council/runs/{id}` instead. Every phase (brief, reviewers, debate, editor, artifacts, judge, persist, mutator) now runs under its own deadline plus an overall cap applied inside `Execute`, which finally bounds the **scheduled (cron)** trigger that previously had no time limit at all; a stage that blows its budget names itself in the terminal run's notes. Each stage emits `council stage start`/`council stage end` logs with `duration_ms` and no credential values. A startup sweep terminalizes `council_runs` rows orphaned by a restart and releases their reservations, so a crashed pass no longer starves the daily cap until its six-hour lease expires. Both synchronous endpoints (`POST /api/mills/council/run`, `/council/dryrun`) are unchanged. New knobs: `LOOM_MILLS_COUNCIL_OVERALL_TIMEOUT` (20m), `_BRIEF_` (2m), `_REVIEWERS_` (3m), `_DEBATE_` (10m), `_EDITOR_` (8m), `_JUDGE_` (3m), `_MUTATOR_` (2m), `LOOM_MILLS_COUNCIL_ASYNC_CONCURRENCY` (1).
