Mills operator no longer seeds the FlexInfer-proxy client with gateway model ids. When `MILLS_JUDGE_BACKEND` / `MILLS_WEAVER_BACKEND` select LiteLLM, `FLEXINFER_JUDGE_MODEL` / `FLEXINFER_WEAVER_MODEL` (and their `*_FALLBACKS`) are gateway-routable ids, and every caller that dialed the proxy client with an empty model inherited them: the council editor's local fallback sent `[or/kimi-k3 or/kimi-k2.7-code]` to flexinfer-proxy and got `Internal error fetching model` on three consecutive council runs (2026-09-07). Gateway roles now resolve the proxy client's model through the aimodels registry and ignore that role's env fallback list; roles left on the proxy are byte-identical.
