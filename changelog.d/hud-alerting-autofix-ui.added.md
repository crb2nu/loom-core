- **Operations ▸ Alerts — a HUD for the alerting and auto-fix domain** (`internal/hud/frontend/src/lib/stores/alerts.svelte.ts`, `src/lib/components/AlertsPanel.svelte`, `src/lib/panelRegistry.ts`, `src/lib/stores/router.svelte.ts`, `src/lib/components/OverviewPanel.svelte`). `internal/hud/domain/alerting` registered eleven desktop REST routes — fired alerts, alert rules, ack, LLM diagnosis, and the five auto-fix proposal/execution endpoints — and rendered none of them, so "what is currently alerting" was answerable only by curl. The new sub-view (key `l`) triages active alerts by severity with per-alert acknowledge and diagnose, lists pending auto-fix proposals with ConfirmDialog-guarded approve/reject over the shared `runAdminAction` toast path, feeds the execution history, and shows the configured rules read-only (rules stay read-only because `PUT /api/alerts/rules` replaces the entire set in one call). Alerts poll through `createPoller` and the shared `apiJson` fetch boundary, so an older daemon that registers no `/api/alerts` resolves to a named not-available state instead of a convincing all-zero dashboard. Overview gains one compact attention lane when alerts are un-acked. The UI copy is deliberately honest about two backend facts: `App.autofixEngine` (`internal/hud/app.go:262`) is declared and never assigned outside tests, so the auto-fix list routes answer `200` with an empty array forever while every auto-fix mutation answers `503` — the panel detects that only from a mutation's 503, because the lists cannot distinguish "nil engine" from "nothing pending" — and even with the engine wired, the `retry` strategy records `"pipeline retry requested"` without re-running anything (`internal/hud/autofix/autofix.go:278` is a placeholder), which the approve confirmation states before the operator commits. Store coverage in `alerts.test.ts` pins the derived pending-proposal rule (proposals carry no status field; approve and reject both append an execution), the nanosecond `time.Duration` and Go zero-time wire formats, the admin-gating asymmetry (diagnose/approve gated, ack/reject not), and the 503 → not-configured transition; `router.svelte.test.ts` pins the new sub-view key.
