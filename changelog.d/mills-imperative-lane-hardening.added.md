- **mills: imperative-lane hardening before first live use** (S7 follow-through). Four gaps closed: (1) the terminal settle now records a `workflow.terminal_settle` event on the escalated item — run id, final state, and the `mills-wf/<run-id>` work-product branch — so the human reviewing the escalation knows what happened and where to look (previously the item escalated mute); the branch prefix moved to `store.WorkflowRunBranchPrefix` as the single source of truth. (2) A wall-clock bound: `workflows.max_run_minutes` (default 180) — the scheduler terminalizes an over-age running imperative run as error via the settling lifecycle CAS, so a wedged run releases its budget reservation and escalates its item instead of holding quiescence (and future canary windows) hostage; wired through an optional `RunDeadlineGate` extension so older gate wirings are unaffected. (3) Template immutability is CI-enforced: shipped `name@version` content hashes are pinned in a golden; editing a shipped version fails with instructions to add a new version instead of terminalizing in-flight runs at runtime. (4) Kernel observability parity: `mills_workflow_start_claims_total`, `mills_workflow_selection_outcomes_total`, and `mills_workflow_runs_terminal_total{state,cause=runtime|deadline}` counters.
