- **Plan→repo bootstrap for new-project handoffs (gated, allow-listed)** (`pkg/mills/bootstrap/bootstrap.go` `Service.EnsureRepo` + shared `mintRepo` helper, `pkg/mills/reconciler.go` `ensureTargetRepo` pre-flight, `pkg/mills/clients/gitlab_projects.go` `ProjectExists`, `pkg/mills/policy.go` `CrossRepoBootstrapGroupAllowed` + `bootstrap_allowed_groups`, `cmd/loom-mills-operator/main.go` wiring): a Mills handoff targeting a project with no GitLab repo yet (e.g. `services/familyforge`) no longer escalates on a git-clone 404 — the operator now pre-flights the repo into existence before dispatch. Before a cross-repo backlog item's pipeline starts, the reconciler checks whether its `TargetProject` exists (GitLab `GET /projects/:id`, a 404 being the trigger, not an error) and, when the plan→repo bootstrap gate is on AND the target's parent group is allow-listed, mints an empty repo initialized with a seeded `main` (README + self-contained green `.gitlab-ci.yml` + `.gitignore` + `AGENTS.md`) so the clone succeeds and the item runs. The mint is recorded in the `bootstrapped_projects` registry (stamped with the triggering backlog item id) so the emitter's demand union sources it. **Safe by default:** creation stays behind the existing two-key gate (`cross_repo.enabled` + `cross_repo.allow_bootstrapped`, off by default) PLUS a new group allow-list (`cross_repo.bootstrap_allowed_groups`, empty = fails closed) so a typo'd or malicious `TargetProject` can never mint a repo in an arbitrary namespace; the manual admin endpoint (`POST /api/mills/projects/bootstrap`) shares the same gated create-repo helper. When bootstrap is disabled or the group is not allow-listed, the pre-flight is a no-op and a missing repo falls through to the clone-time terminal escalation unchanged (composes with the git-clone repository-not-found classifier: that path DETECTS the missing repo, this one ACTS on it before the clone). Idempotent: a registry hit, a live GitLab project (registry backfilled), or a create race are all reconciled to success; a repo is never deleted or overwritten, and a create that succeeds but whose seed commit fails surfaces as an error (the item defers and retries) rather than leaving an empty repo. Pinned by unit tests across all four layers: `ProjectExists` (404→false, 2xx→true+web_url, 5xx→error), the policy two-key + allow-list gate, `EnsureRepo` (registry-hit no-op, GitLab-exists backfill, missing+allowed creates, group-refused, create-race idempotency, fatal seed failure), the reconciler pre-flight (creates/skips/defers/home-noop/nil-noop), and the endpoint's 403-on-disallowed-group.
