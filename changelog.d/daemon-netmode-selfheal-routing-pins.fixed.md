- **Self-heal off-LAN routing so a startup race can no longer silently flip prefer-local pins to the hub** (`internal/daemon/routing.go`, `routing_netmode.go`, `daemon_new.go`, `callpipeline_stages.go`, `metrics.go`): the daemon previously resolved the LAN sentinel once at startup and, on a false "off-LAN" result (one 600ms TCP probe racing a transient network outage), permanently rewrote `local-only`/`prefer-local` pins to `prefer-hub` — sending e.g. `agent_context` vendor-session reads to the cluster pod whose transcript roots are empty (`count: 0, ok: true`) until the next restart. Configured pins are now immutable; the off-LAN upgrade is computed per call from an `offLAN` flag maintained by a background netmode watcher (30s re-probe, 2 consecutive off-LAN probes required to reroute, first successful LAN probe restores local pins immediately). The override is observable: transition log lines name the affected servers, and the new `loom_daemon_routing_pin_override_total{server,pin,effective,reason}` counter counts every call whose pin was upgraded.
