- **Mills stage spawns now survive mobile-hud restarts** (`pkg/mills/pipeline/dispatcher.go`, `pkg/mills/pipeline/runner.go`): every spawn-dispatched stage (plan_slice / implement / pr_self_review) was created UNKEYED — `SpawnWorker.Run` never set `SpawnRequest.IdempotencyKey`, which only the durable workflow runtime used. HUD restart recovery (`classifyInterruptedSpawn`) can only re-drive or re-attach a KEYED spawn, so every mobile-hud rollout mid-turn fail-fasted the in-flight stage with "agent turn driver lost across mobile-hud restart; unkeyed spawn cannot be re-driven" and burned a pipeline attempt (observed 2026-07-26, `PIPE-bl-mills-operator-stop-lever-20260726-…` pr_self_review, 28m of codex work discarded; class `spawn_infra`). `SpawnWorker` now derives a deterministic key per dispatch — `mills-stage:<run>:<stage>:<attempt>` — threaded from the runner's attempt counter via the stage context (new `JobContext.Attempt`, exported `WithStageAttempt`/`StageAttemptFromContext` for custom dispatchers). Keyed + supervised (S4 default-ON) means a restart now RE-ATTACHES to the still-running in-pod turn; keyed unsupervised re-drives it. The attempt number is in the key on purpose: `spawnWithKey` re-attaches to any durable state with the same key including a terminal one, so retries must never reuse their predecessor's key, while a duplicate dispatch of the SAME attempt (crash in the record→dispatch window) now dedupes into an AlreadyExists re-attach instead of a second pod. Attempts stay monotonic across operator restarts (`seedAttempts`), so keys never collide backward.
