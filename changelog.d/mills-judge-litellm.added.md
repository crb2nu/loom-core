- **Mills LiteLLM backend for the rubric judge + weaver** (`cmd/loom-mills-operator/config.go` `MILLS_JUDGE_BACKEND`/`MILLS_WEAVER_BACKEND`, `main.go` `resolveMillsJudgeClient`/`resolveMillsWeaverClient`/`buildLiteLLMModelClient`, `pkg/mills/clients/flexinfer.go` `DisableRegistryFallbacks`): the rubric judge (LLM-judged gates), the council contradiction judge, and the research/weaver stage were hard-wired to the FlexInfer proxy, which does not federate the cluster LiteLLM gateway — so a frontier OpenRouter model like `or/kimi-k3` was unreachable as a judge. `MILLS_JUDGE_BACKEND=litellm` (and independently `MILLS_WEAVER_BACKEND=litellm`) now binds a gateway-backed client (`LITELLM_PROXY_URL` + `LOOM_MILLS_LITELLM_KEY`, same `/v1/chat/completions` + bearer protocol) whose model rides through `FLEXINFER_JUDGE_MODEL`/`FLEXINFER_WEAVER_MODEL`; the default (`flexinfer`) is byte-identical. Judge hardening (truncation recovery, echo-stripping, `FLEXINFER_JUDGE_MAX_TOKENS`, `finish_reason=length` retry) and provider-reported `usage.cost` accounting apply identically on the litellm path because they live in the shared client + `RubricJudge`, not the proxy. Model fallbacks are backend-local: a litellm client suppresses the aimodels-registry (FlexInfer-only) chain so a frontier outage degrades to the env-listed gateway-routable ids (`FLEXINFER_JUDGE_MODEL_FALLBACKS`/`FLEXINFER_WEAVER_MODEL_FALLBACKS`) or nothing — never a proxy model id the gateway would 404. A litellm selection missing its gateway URL or explicit model fails loud at startup and degrades to FlexInfer rather than 404ing per call. Pinned by table-driven backend-selection, litellm-path judge-hardening parity (replaying the captured production fixtures through a gateway-shaped client), and cost-passthrough tests.
