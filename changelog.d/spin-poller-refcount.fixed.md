- **Reference-count the Spinning Room spin-runs poller so navigation no longer strands live spins** (`internal/hud/frontend/src/lib/stores/spinRuns.svelte.ts`, `internal/hud/frontend/src/lib/stores/spinRuns.svelte.test.ts`): the module-singleton `spinRunsStore` is polled by three mounted consumers (`SpinningRoomCard`, `PlansPanel`, `PlansComparePanel`), each driving `start()`/`stop()` as a lifecycle `$effect` pair. `stop()` was unconditional, so when any one consumer unmounted it killed the timer for every other still-mounted consumer. The failure landed on the intended flow: spin a plan from the Mills Overview card → navigate to Work → Plans → the Overview card unmounts → the poller stops → the spin finishes on the durable `/api/mills/spin/runs` backend but nothing polls it, so the completion toast and `landedTick` board refresh are missed until a consumer remounts (intermittent, depending on Svelte 5 teardown-vs-setup flush ordering and whether the spin completes during the gap). The fix makes `start()`/`stop()` acquire/release around an integer refcount: `start()` increments (starting the timer at idle cadence on the 0→1 transition) and always fetches immediately so a newly-mounted consumer gets fresh data; `stop()` decrements (floored at 0, guarding double-release) and only calls `poller.stop()` at the last release. `track()` deliberately does not touch the refcount (it has no paired release) but still keeps the timer live and fast; `syncInterval()` no longer hard-stops on empty history while a consumer is mounted (it keeps a slow idle poll so a later spin is still seen). All existing behavior — adaptive fast(4s)/idle(20s) cadence, `mine`-gated toasts, `landedTick`, the 404 `available` degrade, and toast dedupe — is preserved. The four call sites are unchanged. New tests cover the two-consumer release, full release, Overview→Plans re-acquire, empty-history idle keepalive, double-release safety, and the tracked-spin single-toast regression.
