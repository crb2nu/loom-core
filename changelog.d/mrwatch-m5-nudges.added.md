- **mrwatch M5 transition nudges — durable agent inbox + attention lane** (`internal/hud/mrwatch/notifier.go`, `internal/hud/mrwatch/poller.go`, `internal/hud/bridge/agent_context.go`, `internal/hud/domain/mobile/{deps,helpers,handler_dashboard}.go`, `internal/hud/{app,embed,domain_adapters,domain_adapters_ops}.go`): the branch→MR registry now raises nudges when an MR transitions **into** an unhealthy state (`conflict`, `ci_failed_flaky`, `ci_failed_deterministic`, `automerge_unarmed`, `pipeline_skipped`, `stale_branch`). A new `Notifier` runs as an additive post-poll hook (via `Poller.AddPostPoll`, independent of the M4 shepherd): it (1) diffs each poll's snapshot against the last, emitting once per MR+state and re-emitting only after the state changes away and back; (2) joins the MR source branch to an owning agent through the HUD coordination snapshot; (3) when an owner is found, sends a durable directed message via the agent-context bridge (`agent_message_send`) — body `MR !<IID> (<branch>) entered <state>: <reason> — <web_url>` — with send failures logged and swallowed so the poll goroutine never crashes; and (4) records a read-only `merge`/`conflict` attention-lane item (classified by TYPE first — a conflicted MR maps to the `conflict` lane, every other unhealthy state to `merge`, staying inside the closed `{agent, namespace, merge, conflict}` mobile contract) that the mobile dashboard surfaces alongside the coordination-derived lanes. An unknown branch still fires the attention lane but sends no inbox message. Gated by `LOOM_MRWATCH_NOTIFY` (default ON; a falsey value silences both the inbox sends and the attention lanes).
