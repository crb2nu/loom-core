- **Classify escalations that carry no `[class=…]` marker instead of persisting NULL** (`pkg/mills/pipeline/runner.go`, `pkg/mills/pipeline/escalate.go`, `pkg/mills/pipeline/preflight.go`, `pkg/mills/pipeline/autonomy_gate.go`, `pkg/mills/pipeline/degraded_policy.go`): escalation class was transported as a marker embedded in a human-readable reason string and recovered by re-parsing it, so roughly half the `escalateWithItem` call sites — gate-retry-cap exhaustion, a gate with no `RetryFrom`, drive/adapter/integrator failures, cross-repo, and the policy blocks — persisted `escalation_class`, `escalation_failure_class` and `escalation_retryable` all NULL (`stampEscalationMetadata`'s early return). Those runs bucketed as `unclassified`, which `autoRequeueBaseClass` fails closed to a human, so a genuine infra failure arriving on one of those paths was both invisible in the KPI breakdown AND permanently stranded — live 2026-07-27 it was the largest single bucket (5 of 11 escalations, more than `code`), all sitting at `implement`/`pr_self_review`, i.e. the `RetryFrom` stage of the unmarked gate-retry-cap escalation. Unmarked reasons now fall through to the same needle taxonomy every stage error already uses (`classifyUnmarkedEscalation` → `Classify` over reason + last log tail). This is safe by construction: `Classify` falls through to `ClassCode` and `autoRequeueBaseClass` admits only infra/transient/transient_quota, so unrecognized prose keeps today's exact never-auto-requeued behavior and only evidence matching a KNOWN infra/transient needle becomes correctly classified and requeue-eligible; empty evidence stays unclassified rather than being guessed. The operator-policy blocks (autonomy circuit breaker, degraded mode) now mark themselves `config` — terminal human signals, not code defects — and a health-gate block splits deliberately: fail-closed (health unknown) is `config`, measured-unhealthy is `infra` so bounded auto-requeue can retry once the dependency recovers. Also closes the upgrade seam this creates: an item whose earlier escalations carried the legacy backlog-only dedup marker would have been missed by the now class-aware issue lookup and filed a duplicate, so the escalator falls back to the backlog-only lookup when the class-aware one finds nothing.
