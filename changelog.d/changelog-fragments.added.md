- **Collision-free changelog workflow via `changelog.d/` fragments** (`changelog.d/`, `scripts/changelog/`, `Makefile` `changelog-check`/`changelog-fold`, `.gitlab-ci.yml` `guardrails:docs-cli`, `scripts/ci/check_docs_guardrails.sh`, `pkg/mills/gates/docs_guardrail.go`, `pkg/mills/gates/scope.go`, `cmd/loom-mills-operator/main.go`, `docs/DOCS_MAINTENANCE.md`, `AGENTS.md`): merge requests no longer edit `CHANGELOG.md`'s shared `## [Unreleased]` section — every concurrent MR did, so GitLab flagged server-side conflicts and dropped auto-merge constantly (the union merge driver only exists client-side). Instead each MR drops a per-MR fragment `changelog.d/<slug>.<category>.md` (category ∈ Keep a Changelog set; body = the bullet verbatim). A small Go assembler (`go run ./scripts/changelog`) has two modes: `--check` validates fragments (known category, non-empty body, unique slugs) as a cheap lint wired into the `guardrails:docs-cli` job, and `--fold [--version vX.Y.Z --date YYYY-MM-DD]` merges fragments into the matching `### Category` heading (creating headings in canonical order, tolerating the existing duplicated `### Changed` headings by folding into the first) and deletes them — run at **release** time, not per-merge, so no bot commit races merge-when-pipeline-succeeds. Both docs-guardrail enforcement points now accept a `changelog.d/` fragment as the required documentation update: the CI script's `docs_pattern`, the Mills `docs_guardrail` gate's satisfy pattern (with a remediation message that steers the retry to add a fragment), and the scope gate's docs carve-out (so a Mills implement that writes a fragment doesn't deadlock on "outside slice scope"). The Mills implement prompt now instructs writing one fragment file rather than editing `CHANGELOG.md`.
