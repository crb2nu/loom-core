- **Mills operator is now a first-class citizen of the shared agent-context system** (`pkg/mills/clients/context.go`, `pkg/mills/pipeline/escalate.go`, `pkg/mills/notify/handoff.go`, `pkg/mills/reconciler.go`, `internal/hud/bridge/agent_ops.go`, `cmd/loom-mills-operator/main.go`): the operator has held a long-lived agent-context session since boot and stamped its id on every handoff, but never wrote a single entry to it — so escalation and merge handoffs shipped with `entry_count: 0`, a session-shaped envelope with nothing inside. Three gaps are closed. (1) A new `clients.ContextRecorder` wraps `agent_context_add` over the MCP hub and is called at exactly two decision points: the escalator records a `decision` entry (item, stage, gate/failure classification, MR + issue links) **before** creating the handoff, and the merge notifier records a `finding` entry (item, MR IID + URL, cost, attempts) before its handoff. Both are best-effort — a hub outage is logged and never blocks an escalation or a merge. (2) Backlog-driven pipeline runs now carry the operator's *current* session as `ParentSessionID` (`Reconciler.OperatorSessionID`, resolved per claim so a session re-established after a hub outage is picked up), which already flows to `SpawnRequest.ParentSessionID` and the `LOOM_PARENT_SESSION_ID` stage env — previously only the integrator's fan-out path set it, so every production stage spawn started with no continuity to the operator. (3) `AgentBridge.HandoffList` now polls the union of presence-registered agents and well-known passive inboxes (`mills-merges`, `human-on-call`, overridable via `LOOM_HANDOFF_STATIC_INBOXES`), deduped; those targets never register presence, so every Mills handoff was previously invisible in the HUD.
