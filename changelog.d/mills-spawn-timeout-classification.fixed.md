- **Classify hung/misconfigured spawn agent-CLI failures as retryable infrastructure, not code** (`pkg/mills/pipeline/spawn_class.go`, `pkg/mills/pipeline/error_class.go`, `pkg/mills/pipeline/runner.go`, `pkg/mills/pipeline/spawn_class_test.go`): the `mills-failure-classifier` labeled a `plan_slice` spawn whose agent CLI was killed by the exec deadline (`agent CLI exited 124 (no stderr; stdout: command timed out)`) or that blocked reading stdin without a prompt (`agent CLI exited 1: Reading additional input from stdin...`) as `class=code`. Code failures burn the `MaxAttempts` budget and, interleaved with free-transient spawn re-tries, let runs ride to the `MaxAttempts + TransientRetryCap` total cap (8) — each attempt burning up to 1h of wall-clock, all producing $0.00 and the identical timeout (escalations #356/#357/#358/#359 for the timeout, #351 for the stdin shape). These are spawn/cluster-layer defects, not code bugs: the diff never got a verdict. `Classify` now maps both shapes to `ClassInfra` (retryable, bounded strictly by `MaxAttempts` — never the free-transient budget) via a narrow `SpawnInfraReason` matcher that leaves a genuine nonzero agent exit as `ClassCode`, and the runner's escalation reason now names the defect with a distinct `[reason=spawn-agent-timeout]` / `[reason=spawn-stdin-misconfig]` token so operators and the escalation-class metric stop reading these as code bugs (same pattern as `ErrPipelinePollTimeout` → `ClassInfra` for ci_watch, escalations #149/#153). Tests pin the exact escalation `Reason` bytes from the issues, the sentinel-wrapped production form, and the retryable/non-free/non-terminal `FailureClassification`.
